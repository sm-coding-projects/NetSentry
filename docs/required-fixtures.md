# Required real-device samples and configuration details (needed before Phases 2 and 5)

Nothing below blocks Phase 1. Generic IPFIX and RFC 3164/5424 handling is built from the public
specifications. The UniFi-specific parsers and the calibrated performance targets need real
captures. **Please capture these from the UCG Fiber and drop them into `Fixtures/incoming/`.**
I will sanitize them (replace public IPs, MACs, hostnames, usernames) before they are committed.

## A. Configuration details to confirm in the UniFi Network application

1. UniFi Network application version and UniFi OS version on the UCG Fiber.
2. Exact location and options of NetFlow/IPFIX export (expected: Settings › CyberSecure ›
   Traffic Logging › NetFlow (IPFIX)): server, port, protocol version choices, sampling rate
   options, "sampled" wording, any per-network/VLAN toggles.
3. Exact location and options of remote syslog (expected: Settings › System › Advanced › Remote
   Logging, or Settings › CyberSecure › Traffic Logging › Syslog): host, port, protocol
   (UDP/TCP), which log categories can be forwarded (firewall, IDS/IPS, client/device events,
   triggers), and whether "Traffic Logging" syslog is a separate feature from system syslog.
4. Whether firewall rule logging must be enabled per rule/zone policy ("Log" checkbox) for
   entries to appear in syslog.
5. Whether IDS/IPS ("CyberSecure" / Suspicious Activity) events are forwarded to syslog and in
   which format.
6. Whether DHCP lease events (dnsmasq/odhcpd) and DNS query logs are forwarded.
7. The Mac's IP as seen by the gateway and whether it has a DHCP reservation.

## B. IPFIX capture

On the Mac, with IPFIX pointed at it (port 4739 or 2055), capture ~10 minutes including at
least one template refresh cycle:

```bash
sudo tcpdump -i en0 -w ~/Desktop/ucg-ipfix.pcap udp port 4739
```

From this I will derive: template contents (information elements, enterprise IEs, whether
biflow/reverse fields are used), options templates (sampling rate, interface names), observation
domain ids, refresh interval, datagram sizes, sequence-number behaviour, whether NAT fields are
present, IPv6 usage, and real record rates for `docs/performance-targets.md`.

## C. Syslog samples (one file per family, ~50 lines each, raw bytes)

```bash
# capture raw UDP payloads without altering them
sudo tcpdump -i en0 -A -w ~/Desktop/ucg-syslog.pcap udp port 5514
```

Families required:

| Family | How to provoke |
|---|---|
| Firewall allow / deny (zone-based policy with logging on) | Create a test rule with logging; hit it from a client |
| IDS/IPS alert (CyberSecure) | Use a benign test signature (e.g. EICAR download or `testmyids.com`) |
| Authentication (UniFi OS admin login success/failure, SSH) | Log in/out of the console |
| VPN (WireGuard/L2TP/Teleport/site-to-site connect/disconnect) | Connect a VPN client |
| DHCP lease assign/renew/release | Reconnect a client |
| DNS (if forwarded) | Any DNS traffic |
| System events (interface up/down, WAN failover, updates, reboot) | Reboot or unplug a port |
| Device/client events (client connected/disconnected/roamed, if the gateway forwards them) | Join a client |
| Anything with RFC 5424 structured data, if the gateway emits it | – |

Also useful: one sample of the very first message after gateway boot, and the timestamps'
timezone behaviour (does the gateway send local time without a zone?).

## D. Until real samples exist

* IPFIX fixtures are generated by `nsgen` from public IANA IE definitions, covering every decoder
  test case listed in the requirements.
* Syslog fixtures use publicly documented Linux **netfilter LOG** format (`IN= OUT= MAC= SRC= DST=
  LEN= … PROTO= SPT= DPT=`), which UniFi gateways are known to use with a bracketed rule prefix.
  The exact prefix grammar and all other UniFi families are marked *unverified* in the parser
  registry until confirmed, and messages fall back to the generic parser with `parse_status =
  partial`.
